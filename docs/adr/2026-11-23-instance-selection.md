# ADR 2026-11-23：按会话选择实例，不设全局默认

状态：已接受。

## 背景

同一台机器上常有多个 agent 会话并行，它们可能需要不同的思源实例。实例之间可能是不同数据，也可能是互相同步、但存在延迟的副本。如果有一个全局可写的“当前默认实例”，一个会话切换后，其他会话会在不知情的情况下改用新实例，写入落到错误的地方。

DSH 的每次 shell 调用都是新进程，环境变量无法跨调用保留；但每次调用都带有 `DSH_SESSION_ID`。

## 决策

**实例按以下顺序选择：`-i NAME` > `SYC_INSTANCE` > 当前会话的 `syc use` 记录 > 仅配置了一个实例时使用该实例。都不满足时报错，列出全部实例的名称和 URL，以及 `syc use <name>`、`syc -i <name> ...` 两种选法。** 不存在全局默认实例，配置中也没有 `default` 项。

- `syc use` 只写当前会话的记录。没有可识别的会话时报错，提示改用 `-i` 或 `SYC_INSTANCE`。
- 会话识别是一个有序的 `(harness, 环境变量)` 列表，目前只有 `("dsh", "DSH_SESSION_ID")`。只有确认某个宿主的会话变量后才加入，不猜测变量名。
- 每条访问实例的命令都在 stderr 输出 `syc: instance=<name> (<source>)`。这一行用于事后核对，不能代替显式选择。
- 子 agent 在 DSH 中是独立会话，不继承父会话的选择，会按上面的规则报错，不会悄悄改用其他实例。skill 要求委派任务时写明实例。

会话记录存于配置目录下的 `state.db`（SQLite，标准库自带）：

- 一张表 `sessions(harness, session_id, instance, updated_at)`，主键为 `(harness, session_id)`。用 `harness` 列区分宿主，新增宿主不需要改表结构。
- 用 `PRAGMA user_version` 和按顺序执行的迁移函数管理结构变化，当前版本为 1。
- 每次写入后，每个 harness 只保留 `updated_at` 最新的 9999 行。被清掉的旧会话再次调用时会报错要求选择实例，不会用错实例。
- 设置 SQLite busy timeout 处理并行写入，不另加锁。

## 依据

- 并行会话共享全局默认会造成静默误写，这一风险在多会话工作方式下会实际发生；按会话隔离加上报错，代价只是每个会话开头多执行一次 `syc use`。
- 按工作目录限定作用域（类似 `.python-version`）不能解决同一目录下的多个并行会话。
